# EasyPDF V2 — deployment guide

This package is a static frontend for **https://easypdf.co.in**. It retains the existing HTML tool routes and browser-side tools. The backend remains a separate Render service.

## 1. Before deploying

1. Keep a backup of the currently deployed frontend.
2. Extract this ZIP. The folder `pdftoolkit-main/` is the project root.
3. Review `assets/config.js`. It is configured for `https://api.easypdf.co.in` and a 25 MB client-side limit.
4. Confirm that the backend is reachable at `https://api.easypdf.co.in/health`.
5. Confirm backend CORS allows `https://easypdf.co.in`. Add `https://www.easypdf.co.in` only if that hostname is actually used.
6. The frontend API key is blank by default. Do not put a private backend secret in this file; every visitor can read it.

## 2. Deploy with GitHub + Render

### GitHub
1. Extract the ZIP and open `pdftoolkit-main/`.
2. Commit the **contents** of that folder to the frontend repository (not the outer ZIP folder).
3. Keep the existing directory structure, especially all tool folders and `assets/vendor/`.
4. Push to the branch connected to Render.

### Render static site
The included `render.yaml` defines a static site:
- Build command: `python3 build_pages.py`
- Publish directory: `.`
- Static security headers: `nosniff`, strict-origin referrer policy, and a same-origin camera policy for the scan-to-PDF workflow.

If the existing Render service is already configured correctly, you can keep it and copy the new files over rather than creating a second service. Do not change the custom domain or DNS settings as part of this frontend deployment.

`build_pages.py` only refreshes `sitemap.xml`. It deliberately does **not** regenerate or overwrite the hand-authored tool pages.

## 3. Configure Google integrations

### Google Analytics 4
In `assets/config.js`, set:
```js
const GA_MEASUREMENT_ID = "G-XXXXXXXXXX";
```
Use the Measurement ID from the GA4 web data stream. Leave it blank if you have not created the stream. The script loads only when the value has the expected GA4 format.

### Google AdSense
After AdSense approval, set:
```js
const ADSENSE_CLIENT_ID = "ca-pub-XXXXXXXXXXXXXXXX";
```
The AdSense library will load, but this package does not invent ad-unit IDs or insert ads into the upload/workspace area. To display an ad, add a real AdSense slot only in a content section outside `.start` and `.ws`, for example:
```html
<div class="ad-slot" data-ad-slot="YOUR_NUMERIC_SLOT_ID"></div>
```
Replace the placeholder with the slot ID generated by AdSense. Do not add ads inside file upload, conversion, progress, preview, or download controls.

### Search Console
The existing verification file `google87958db414d318c8.html` is retained. Keep it deployed at the site root. Submit `https://easypdf.co.in/sitemap.xml` in Search Console.

## 4. Backend contract and paused tools

The included `UPGRADE-NOTES.md` records the backend paths documented for this project. The frontend expects downloadable response bytes from server conversion endpoints and should be tested against the live backend before announcing them as working.

The following tools are deliberately paused in this frontend because the supplied API contract does not document their required endpoints:
- Unlock PDF — requires `POST /api/unlock`
- PDF to Excel — requires a documented and tested `POST /api/pdf-to-excel`
- Repair PDF — requires a documented and tested `POST /api/repair`

Their existing URLs are preserved, but conversion is blocked with an explanatory message instead of sending requests to unverified routes. To enable them, implement the backend endpoint, add it to the OpenAPI schema, verify its response type/filename and deletion behavior, then remove the corresponding `unavailable` flag in `assets/easypdf.js`.

## 5. Admin dashboard status

A secure admin dashboard is **not included**. The supplied backend API description does not provide admin authentication, role-based authorization, secure sessions, or persistent admin data endpoints. A static password prompt in JavaScript would expose credentials to every visitor and is not a safe substitute. Build the admin feature in the backend first, then connect a protected admin UI.

## 6. Test before production

Run these checks from the project root:

```bash
python3 build_pages.py
python3 tests/smoke_test.py
node --check assets/easypdf.js
node --check assets/site-enhancements.js
node --check assets/config.js
node --check pwa.js
node --check sw.js
```

Then test in a real browser:
1. Open the homepage on Android Chrome and desktop.
2. Toggle Light/Dark; refresh and confirm the choice persists.
3. Test search, tool cards, and every existing trailing-slash tool URL.
4. Test Images to PDF, Merge PDF, Extract Pages, Rotate PDF, Scan to PDF, and Edit PDF with non-sensitive sample files.
5. Test each documented server conversion with small sample files. Confirm upload progress, correct output file type, download filename, and PDF preview where the result is a PDF.
6. Test a rejected file type, a file above 25 MB, a wrong password, and a network interruption.
7. Confirm the service worker updates to `easypdf-v5` after deployment. If an old UI remains cached, close installed app windows and clear the old site cache once.
8. Check Search Console sitemap status and GA4 real-time reporting after configuring the IDs.

The automated checks validate static files and JavaScript syntax; they do not replace live conversion tests against the backend.

## 7. Rollback

If a regression appears, redeploy the previous Git commit in Render. The backend service and DNS do not need to be changed for a frontend rollback.
